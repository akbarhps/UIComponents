# dist / snippets final review

Verdict: NOT READY. index.html guards keep the showcase working (web-checks 43/43, 0 console errors; every guard wraps exactly its own demo block, and no function or const moved into a block is used outside it). `--check` passes and dist matches the build output. Consumer use fails in several ways. The reports' "30/30 ERRORS: none" result only covered page load, not interaction.

Evidence: a throwaway CDP script loads every SNIPPETS.md block into consumer pages with dist/ui.css + ui.js (scratchpad snip-check.mjs). Results: menu, combo, multi, tag, autocomplete, date picker, file input, toast, modal (open + Esc), tabs, accordion, stepper, pagination and row selection all work. The errors below are the ones it hit.

## Findings
web/SNIPPETS.md:73: bug: the multi-select snippet has no `.multi__empty`. Opening it throws `TypeError: Cannot set properties of null (setting 'hidden')` (index.html:2484 `empty`). Fix: add `<div class="multi__empty" hidden>No matches</div>` inside `.multi__list` (it is in index.html:1306).
web/build-dist.mjs:33: bug: ui.js declares 64 top-level globals in the shared global lexical scope (`app`, `sidebar`, `overlay`, `observer`, `sections`, `CHECK`, `MONTHS`...). If a consumer page has `const app = ...`, ui.js fails with `SyntaxError: Identifier 'app' has already been declared` and nothing initialises (verified). Fix: wrap the scripts in an IIFE in the build and export the documented factories, for example `Object.assign(window,{showToast,openOverlay,closeOverlay,setFieldError,createGrid,initPicker,bindSimpleFilters,bindColumnFilters})`.
web/index.html:2153: bug: each guard checks only the root id. If a consumer keeps `id="overlay"` (a very generic id) but renames the buttons, `getElementById('openModal').addEventListener` throws and every init after line 2153 is skipped (combo stayed dead, verified). The same applies to formOverlay, drawerOverlay, editOverlay, cmdkOverlay, stepperDemo, selectionTable and toastDismissible. Fix: guard on every id the block dereferences, or use `?.` on each demo `getElementById(...)`.
web/SNIPPETS.md:149: bug: the snippet ids are the demo ids, so ui.js auto-wires the demo. `#sheet` gets a grid with demo data at load, and the init line ("NOT auto, call createGrid('sheet', ...)") then initialises it a second time, so the toolbar listeners are bound twice. The init lines are also wrong for these sections: #filterTable (420), #columnTable (443), #sortTable (462) and #cmdkOverlay (479) are all auto-wired. On consumer pages the cmdk demo commands throw (`goTo('buttons')` gives null.scrollIntoView; "Toggle sidebar" calls `sidebarToggle.click()` on null). Fix: give these snippets non-demo ids (for example `mySheet`) and correct the init lines.
web/SNIPPETS.md:3: bug: line 3 says "IDs below are demo-only: change them", but Stepper (347) and Row selection (395) say "keep those ids", and the modal/drawer demo wiring only works with the ids kept. Fix: say per section whether to keep or change the ids.
web/index.html:2330: bug: bindSimpleFilters (2330), the sort click (2364) and bindColumnFilters (2398) call `closest('.demo')._resetPage()`. The filter, column and sort snippets have no `.demo` wrapper, so typing or sorting throws `Cannot read properties of null (reading '_resetPage')` (verified for all three). `.demo` is also the showcase card style (padding 30px plus a border), so wrapping consumer tables in it is wrong. Fix: `closest('.demo')?._resetPage?.()` (no change on the showcase), and pagination should get a non-`.demo` hook later.
web/SNIPPETS.md:266: bug: the modal form snippet has no `#fm-email`, and the auto-wired submit handler reads `email.value`, so submit throws (verified). Fix: add the email field from index.html:2044-2049, or say in the init line that submit is not wired.
web/build-dist.mjs:10: bug: `core.autocrlf=true` is set in this repo and there is no .gitattributes. After web/dist is committed, a fresh clone checks out index.html and dist with CRLF. The build adds LF-only header and join lines, so `--check` reports STALE on a clean checkout, and rebuilding writes mixed line endings. Fix: `.replace(/\r\n/g,'\n')` on index.html and on the dist files before comparing, or add `.gitattributes` with `web/** text eol=lf`.
web/build-dist.mjs:81: nit: the "bytes" in the log are `css.length` (UTF-16 code units). ui.css has 1737 non-ASCII chars (the `── Name ──` box-drawing in the section comments), which is why the log says 53,788 while the file on disk is 57,262 B (ui.js: 76,313 chars vs 76,327 B). Both reports are correct; neither is drift. Fix: `Buffer.byteLength(css)`.
web/build-dist.mjs:28: nit: the sprite is skipped whenever `#i-check` exists. A consumer page that defines its own i-check gets none of the other 27 icons (i-chevron missing, verified). Fix: mark the injected svg (for example `id="ui-sprite"`) and test for that, or inject only the missing symbols.
web/build-dist.mjs:70: nit: the hook lookup accepts any word in any quoted string in ui.js (`open`, `success`, ...), so a misspelled class that happens to match such a word still passes `--check`. The `icon ids:` line (SNIPPETS.md:5) is not checked either. It currently matches the 28 injected symbols, and `#i-plus` is included.
web/build-dist.mjs:10: nit: if index.html or SNIPPETS.md is missing, the script dies with a raw ENOENT stack. That is acceptable for a dev script.
skills/ui-components/SKILL.md:3: scope-creep: the description change ("not for Manual Logger") is not part of this task. dist-report says it was already uncommitted before the task, so keep it out of this commit or confirm it on purpose.
