## Should-fix

1. `wpf/tests/Tests.Pickers.cs:141-150`: P10 `outside click closes` fails deterministically with `-Only pickers` (split-only-pickers.txt and -rerun, both FAIL) and passes in the full run. This is the only status difference between the union of the single-area runs and the full run, so the plan's "each area alone equals the full run" bullet is not met. Cause (hypothesis, not run): the click point is computed from `dateSection`'s BoundingRectangle (`RectPart(dateSection,"X")+Width-60`, `Y+20`) and posted as a window message; nothing in the area scrolls the card into view, so with the page at scroll top (isolation) the card is below the viewport and the posted click lands outside the window or on nothing, whereas earlier areas in the full run leave the page scrolled near the pickers. It is a pre-existing defect hidden by run order, not a move error. Route it: add it to `handoff/pickers-next.md` (fix: bring the card/trigger into view before computing the point, e.g. `Drv.Focus(pickTrigger)` then re-read the rect and assert `!dateSection.Current.IsOffscreen`, or assert the point is inside the window rect) and record it as the known `-Only pickers` failure in `handoff/tests-split.md` until fixed. Phase 1 must not change it (pure move). The same fragility means any change in the scroll state left by an earlier area can flip P10 in the full run.
2. No evidence file for the remaining Phase 1 verify bullets: `build-tests.bat split dropdown` compiling Core + Dropdown only, `-Only nav` on that exe printing `FAIL  area nav not compiled` with exit 1, `-Only nope` printing `FAIL  unknown area nope` with exit 1, and a no-`-Only` run. The code paths read correctly, but the handoff dir has only the `split-only-*` and full runs. Capture these three runs into `handoff/split-only-*.txt` (cheap: seconds each) before Phase 5. `wpf/tests/bin/split/UIAutomationTests.exe` (10:46:58) is currently a full build (contains the strings of all areas), so later phases are not affected.

2. `run-hidden.ps1:80,102`: with an in-session call (`.\run-hidden.ps1 -Only a,b`, not `pwsh -File`) PowerShell binds the comma array to `[string]` joined by a space, giving `--only a b`, which silently runs only `a`. Plan docs always use `pwsh -File`, so only a trap for hand-typed commands; fix with `[string[]]$Only` and `($Only -join ',')` if wanted.
